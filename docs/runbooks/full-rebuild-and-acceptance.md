## 1. When to rebuild, and what it resets

Rebuild when you want to prove that Git alone produces the lab, for example after many live changes, a cluster-creation change in `scripts/setup-hub-spoke.sh`, or a lab that is beyond repair. For a reboot or a paused lab, use `make stop` / `make start` + `make post-bootstrap` instead (lifecycle runbook).

| Reset by a rebuild | Kept |
|---|---|
| All three k3d clusters and every object in them | Everything in Git (all five repositories) |
| moto (queues, tables, IAM users and keys) | Secrets in `~/.config/gitops-lab` (passwords, OIDC client secrets, remote-write credentials) |
| Spoke and Headlamp tokens (new 30-day tokens) | The lab TLS certificate in `~/.config/gitops-lab/tls` (mkcert CA stays trusted on Windows) |
| Keycloak sessions (everyone logs in again) | Host leftovers outside the lab (`argolab`, kind clusters) |
| Application UIDs, Argo CD history | |

## 2. Pre-flight

```bash
# 1. Nothing else may hold host ports 80/443 (the setup also checks this and stops with a message)
k3d cluster list                                   # argolab (jenkins-argo lab) must show 0/1 servers
docker ps --format '{{.Names}} {{.Ports}}' | grep -E ':(80|443)->'   # only k3d-hub-cluster-serverlb, or nothing

# 2. Every repository on main and pushed: the rebuild deploys what is on GitHub, not your working tree
for r in gitops-control-plane platform-catalog platform-charts tenant-workloads orders-processor; do
  git -C ${REPOS_DIR:-..}/$r fetch -q; echo "$r: $(git -C ${REPOS_DIR:-..}/$r status -sb | head -1)"; done

# 3. Lab secrets present (directory 700, files 600; values never printed)
ls -l ~/.config/gitops-lab ~/.config/gitops-lab/tls
```

**Expected:**
* `argolab` stopped; no foreign container on 80/443.
* Every repo shows `## main...origin/main` with nothing ahead or behind.
* The secrets directory exists.

On a brand-new machine the secrets are generated by `make setup` and `make post-bootstrap` themselves (see README *Quick Start*). For a trusted HTTPS certificate, install mkcert once on Windows (`winget install FiloSottile.mkcert`, then `mkcert -install`). Otherwise the lab uses a self-signed fallback.

## 3. Rebuild

Run the steps in order. Each is idempotent. For an unattended run, start them with `nohup` and a log, because a closed terminal (SIGHUP) would stop a long step.

| Step | Command | What it does | Expected time |
|---|---|---|---:|
| 1 | `make teardown` | Deletes the three k3d clusters, `moto-cloud` and the `k3d-cloud-net` network. Nothing outside the lab | ~1–16 s |
| 2 | `make setup` | Checks 80/443 are free, creates the network, moto, `k3d-hub-cluster` (`127.0.0.1:80/443`), `k3d-spoke-nonprod` (`:8081`), `k3d-spoke-prod` (`:8082`); installs Traefik and the lab certificate (`setup-local-tls.sh`); installs Argo CD and the AppProjects; registers the spokes; creates the Headlamp credentials | ~3 min (184 s) |
| 3 | `make bootstrap` | Applies the root Application; Argo CD deploys everything else from Git | ~1 s |
| 4 | `make post-bootstrap` | Waits for the tenant workloads, restarts CoreDNS for `*.localhost`, waits for Keycloak, provisions worker IAM keys in moto (accounts 111111111111 / 222222222222), restarts the workers, adopts the `argo-cd` Application, re-syncs anything stuck, runs the smoke test | ~5 min (298 s) |

On 2026-10-04 the whole sequence took **484 s, with no manual step**.

## 5. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `make setup` stops with *"Host port 80/443 is already published by: …"* | Another lab holds the ports, usually `argolab`. Stop it (`k3d cluster stop argolab`); lifecycle runbook **Issue H** |
| `make setup` stops with no message right after a step header | A pipeline whose `grep` matched nothing aborted under `set -euo pipefail` (the 2026-10-04 defect, fixed in `5a619cd`). When writing setup code, guard optional matches with `{ grep … \|\| true; }`. CI cannot catch this; only a rebuild exercises the setup path |
| `docker ps` hangs, `github.com` does not resolve in the clusters (`server misbehaving`) | Docker Desktop engine hang; lifecycle runbook **Issue A**. Restart Docker Desktop, then start the rebuild again from step 1 |
| An Application stays *OutOfSync* / *Progressing* after step 4 | Re-run `make post-bootstrap` (it re-syncs what is stuck). For `argo-cd` itself: manual sync is by design |
| Orders not processed after a rebuild | Workers need new moto keys: `make post-bootstrap` (step 4) does it; lifecycle runbook **Issue F** |
| Certificate warning on `https://*.localhost` | mkcert CA not trusted yet: on Windows `mkcert -install`, then `make local-tls` |
| You want to change hub ports | Change `scripts/setup-hub-spoke.sh` and rebuild. **Never** `k3d cluster edit … --port-delete` on a running hub (Issue H) |

## 6. After the rebuild
* New tokens are valid for 30 days. `SpokeTokenExpiringSoon` warns 7 days before expiry; renew with `make maintain` (manual by owner decision) or `make post-bootstrap`.
* Record the run when a rebuild is part of a remediation plan (implementation report: timings, any manual step, the checks above), and have the other party validate it.
